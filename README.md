# 했냐옹 🐱

중요한 일정을 잊어버리거나, 해야 할 일을 놓친 경험이 있으신가요?

**했냐옹**은 프로젝트별 일정과 할 일, 개인 플랜을 한곳에서 관리하는 서비스입니다. 캘린더와 홈에서 계획을 확인하고, 연결한 Slack 계정으로 일정 알림을 받을 수 있습니다.

- **서비스:** [haetnanyong.vercel.app](https://haetnanyong.vercel.app/)
- **기술:** Nuxt 4 · Vue 3 · TypeScript · Nitro · Neon PostgreSQL · Slack API
- **주요 화면:** 홈 · 플랜 · 프로젝트 상세 · 캘린더 · 리마인더 · 마이페이지

## 누구를 위한 서비스인가요?

약속·학습·업무·사이드 프로젝트를 함께 관리하다 보면 계획이 흩어지고 기한이 지난 작업을 놓치기 쉽습니다. 여러 프로젝트를 진행하거나 개인 계획을 정리하고 싶은 사람, 평소 사용하는 Slack으로 일정 알림을 받고 싶은 사람을 대상으로 만들었습니다.

캘린더에서는 월간 일정을, 홈에서는 오늘 일정과 오늘부터 3일 이내 마감인 미완료 할 일, 기한이 지난 미완료 할 일을 확인할 수 있습니다.

## 이렇게 사용해요

[배포 사이트](https://haetnanyong.vercel.app/)에서 회원가입한 뒤 아래 사용 순서대로 확인할 수 있습니다. 별도 테스트 계정은 제공하지 않습니다. Slack을 연결하지 않아도 일정·할 일 관리와 캘린더를 사용할 수 있습니다.

코드의 요청 제한은 같은 IP 기준 회원가입 1시간당 20회, 로그인 10분당 10회입니다. 같은 공인 IP에서는 횟수를 공유하고 실패·차단 요청도 집계합니다. 제한에 걸리면 응답 헤더를 기준으로 다시 시도 가능한 KST 시각을 안내합니다. 상세 기준은 [운영 안내](docs/vercel-operations.md)를 참고해주세요.

대표 흐름은 **프로젝트에 일정을 등록하고 Slack 알림을 받는 과정**입니다.

### 일정 등록·조회 확인

1. 회원가입하거나 로그인합니다. 닉네임은 비워두면 자동 생성됩니다.
2. **플랜 → 플랜 등록**에서 일정을 선택하고 기존 프로젝트를 고르거나 새로 만듭니다.
3. 제목과 시작·종료 시각을 입력해 저장하고, 프로젝트 상세와 캘린더에서 확인합니다.

저장한 일정이 프로젝트 상세와 캘린더에 표시되는지 확인합니다. Slack을 연결하지 않아도 여기까지 사용할 수 있습니다.

### Slack 알림 수신 확인

4. **마이페이지 → Slack 연결**에서 알림을 받을 워크스페이스와 본인 계정을 승인합니다.
5. **테스트 DM 보내기**를 눌러 메시지 수신을 확인합니다.
6. 일정 상세에서 알림 시각을 설정하고 리마인더에서 예약 상태를 확인합니다.
7. 설정한 시각에 Slack 봇 DM이 도착하는지 확인합니다.

예약 상태와 별도로 테스트 DM과 실제 예약 메시지가 각각 도착하는지 확인합니다.

알림은 현재부터 1분 이후, 120일 이내로 예약할 수 있습니다. 시연할 때는 미래 일정을 등록하고 알림 방식을 **직접 지정**으로 선택해 몇 분 뒤로 설정합니다. 시간 입력은 한국 표준시(KST) 기준이며, 종일 일정의 종료일은 포함하지 않습니다.

Slack 알림을 확인하려면 본인이 참여한 워크스페이스에 앱을 연결해야 합니다. 워크스페이스 정책에 따라 관리자 승인이 필요할 수 있어요. 연결·설정 방법은 [Slack 연결 안내](docs/slack-oauth.md)를 참고해주세요.

`SCHEDULED`는 예약 접수, `ELAPSED`는 예약 시각 경과를 나타냅니다. 실제 수신 여부는 테스트 DM과 예약 메시지를 Slack에서 각각 확인합니다.

## 이번 과제에서 구현한 범위

| 영역          | 구현 내용                                                                       |
| ------------- | ------------------------------------------------------------------------------- |
| 플랜 관리     | 프로젝트 소속·개별 일정과 할 일 등록·조회·수정·삭제, 할 일 완료 처리            |
| 프로젝트 관리 | 프로젝트 등록·조회·수정·삭제·보관·복원, 완료된 프로젝트의 보관 제안             |
| 계획 확인     | 오늘 일정·3일 이내 마감·지연된 할 일을 보여주는 홈, 월간 일정 캘린더            |
| 계정          | 회원가입·로그인·로그아웃, 닉네임·비밀번호 변경, 다른 기기 로그아웃, 회원 탈퇴   |
| Slack         | OAuth 연결·해제, 테스트 DM, 일정 알림 예약·취소·상태 재확인                     |
| 공통 UI       | 모바일 대응, 밝은·어두운 테마, 한국어·영어, 도움말·확인 모달, 오류·빈 상태 안내 |

보관 제안은 항목이 하나 이상 있고 모든 일정이 종료되었으며 모든 할 일이 완료된 프로젝트에 표시합니다. 수동 보관은 미완료 프로젝트에도 사용할 수 있습니다.

종료된 일정은 목록과 캘린더에서 흐린 스타일로 구분하며 상세 조회와 수정은 계속 가능합니다. 알림은 예약 시각이 지나면 `예약 시간 지남`과 `다시 예약`을 표시합니다. 이 표시는 실제 발송 성공을 의미하지 않습니다.

캘린더에서는 보관된 프로젝트의 지난 일정도 이력으로 확인할 수 있습니다.

이번 범위는 개인의 계획 등록·확인·알림 수신에 집중했습니다. 로그인과 DB는 사용자별 데이터 유지를 위해, Slack은 실제 알림 수신을 위해 연결했습니다. 팀원 초대·공유 권한 등 협업 기능은 향후 확장 범위입니다.

## 만들면서 이렇게 정했어요

- **일정과 할 일 구분:** 일정은 시작·종료 시각을, 할 일은 기간과 완료 상태를 관리합니다. 캘린더 표시와 Slack 알림은 일정 기준입니다.
- **프로젝트 선택:** 간단한 개인 약속이나 할 일은 프로젝트 없이도 등록할 수 있도록 했습니다.
- **서버 세션 인증:** HttpOnly 쿠키로 세션을 전달하고 DB에는 토큰 해시를 저장합니다. API에서 로그인 여부와 데이터 소유권을 확인합니다.
- **불확실한 알림 처리:** 중복 예약을 줄이기 위해 결과가 불확실한 요청은 상태를 보존하고 Slack 예약 목록과 다시 비교합니다.
- **화면 설정 저장:** 언어와 테마는 브라우저 쿠키에 저장합니다. 같은 브라우저에서 선택값을 기억하며 기기 간 동기화는 지원하지 않습니다.

프론트엔드는 **입력값 검증 → API 요청 → 성공·실패 처리 → 화면 갱신**으로 연결했습니다. [ItemEditor.vue](app/components/workspace/ItemEditor.vue)에서 입력과 중복 제출을 확인하고, [useApi.ts](app/composables/useApi.ts)로 요청합니다. 실패하면 입력을 유지하며 오류를 표시하고, 성공하면 저장 결과를 상위 화면에 전달합니다. [plans.vue](app/pages/plans.vue)는 관련 목록을 갱신하고 생성한 항목에 맞는 프로젝트 상세나 개별 플랜 탭으로 이동합니다.

## AI 활용과 검증

웹 ChatGPT는 서비스 아이디어, 화면·데이터 구조 정리와 고양이 이미지 제작에 활용했습니다. IDE의 AI 코딩 도구는 화면과 API 구현, SQL 작성, 오류 수정과 자동 검사에 활용했습니다.

필요한 기능과 화면 구성, 개발 순서는 제가 정했습니다. Neon·Slack·Vercel 계정 생성과 설정, 환경변수 입력, 배포와 실제 사용 확인도 직접 진행했습니다. 코드와 검사 코드는 AI의 도움을 받았고, 사용 중 발견한 문제와 원하는 동작을 전달하며 수정했습니다.

### 사례 1. 특정 PC에서 언어·테마 선택이 반영되지 않는 문제

특정 PC에서 선택창은 열리지만 항목을 누르면 닫히기만 하고 언어·테마가 바뀌지 않았습니다. 다른 기기에서는 정상이고 같은 PC에서도 자동 조작으로는 변경되어, 발생 환경과 직접·자동 조작의 차이, 저장소 코드를 AI에 전달해 원인을 좁혔습니다.

분석에서 포커스 목적지인 `relatedTarget`이 `null`이면 메뉴를 즉시 닫는 코드를 확인해 보완했습니다. 로컬 자동 검사 후 문제 PC에서도 실제 마우스로 선택이 반영되는 것을 직접 확인했습니다. 수정 전 이벤트 순서를 직접 기록한 것은 아니므로 원인을 확정한 것과 수정 후 정상 동작을 확인한 것은 구분했습니다.

### 사례 2. Slack DM이 도착하지 않는 문제

AI의 도움으로 Slack 알림을 구현한 뒤 실제 계정에서 DM이 도착하지 않는 현상을 확인했습니다. API 응답의 `messages_tab_disabled` 메시지를 근거로 Slack 공식 문서를 활용하여 앱의 Messages Tab 설정을 확인하고 수정했습니다. 이후 테스트 DM과 실제 예약 메시지의 수신을 확인했습니다.

이 과정에서 화면의 연결 표시나 예약 상태만으로 정상 동작을 판단하지 않고, 실제 Slack 계정에서 메시지 수신까지 확인하는 것을 검증 기준으로 삼았습니다.

### 사례 3. 프로젝트 보관 기능의 조건 보완

프로젝트의 모든 일정이 종료되고 할 일이 완료되면 보관 여부를 묻도록 요청했습니다. AI 도구를 활용한 코드 점검에서 화면의 완료 판단에만 의존하던 부분을 확인했고, 제안을 통한 보관 요청은 서버에서도 조건을 검사하도록 보완했습니다. 화면 확인 후 상태가 바뀔 수 있으므로 조건에 맞지 않으면 요청을 거절하고 모달 안에 안내하도록 했습니다.

AI 도구의 모의 API 브라우저 검사로 보관 실패 안내, 재시도 후 보관함 이동, 복원 직후 제안이 다시 뜨지 않는 동작을 확인했습니다. 실제 DB의 동시 요청 검증과는 구분해 기록했습니다.

기획, DB 설계, 이미지 제작, 프론트·백 구현에 활용한 내용은 [AI 활용 상세](docs/ai-usage.md)에 정리했습니다.

## 아직 해결하거나 확인해야 할 부분

- **대량 데이터 성능:** 작업 화면은 사용자 소유의 프로젝트·할 일·일정·알림 전체 목록을 불러오며 페이지네이션은 없습니다. 실제 운영 데이터 규모에서 응답 시간과 응답 크기를 측정하고 조회 범위를 나눌 필요가 있습니다.
- **동시 요청의 데이터 일관성:** 보관 조건·알림 상태 변경을 보호하는 검사는 구현되어 있지만, 일정·할 일 변경과 알림·연결 변경·탈퇴가 겹치는 모든 상황의 일관성을 보장하지는 않습니다. 운영 DB에서 경합을 검증하고 필요한 경로의 잠금을 보완해야 합니다.
- **Slack 장애와 취소 복구의 운영 검증:** 불확실한 예약 결과 보존·재확인과 탈퇴 후 취소 큐·정기 재시도는 구현되어 있습니다. 권한 철회·응답 지연·Slack 장애 시 상태가 유지되는지, 미처리 취소가 정기 작업으로 정리되는지는 실제 운영 환경에서 추가 확인해야 합니다.
- **현재 제공하지 않는 기능:** 이메일 인증·비밀번호 재설정·이메일 주소 변경, Slack Org 전체 설치·Token Rotation은 지원하지 않습니다.

- 도움말에 GIF나 짧은 영상을 넣어 사용 방법을 쉽게 이해할 수 있도록 개선하고 싶어요.
- 캘린더에서 날짜를 누르면 그날의 일정 목록과 상세 내용을 모달로 보여주려고 합니다.
- 공휴일과 주말 표시를 보강하고 모바일 캘린더도 읽기 편하게 개선할 계획입니다.
- 프로젝트에 다른 사용자를 초대하고, 팀장·팀원으로 역할을 나눠 함께 사용할 수 있게 하고 싶어요.
- 백엔드·프론트엔드처럼 필요한 유닛을 만들고 일정·할 일에 유닛이나 팀원을 지정할 수 있도록 확장하려고 합니다. 팀장은 프로젝트 전체 일정과 팀원의 Slack 연동 여부를 확인할 수 있도록 할 계획입니다.
