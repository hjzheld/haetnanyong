# 언어 선택

테마 옆의 지구본 버튼에서 위로 열리는 언어 팝오버로 한국어·English를 선택합니다. 로그인 전후 같은 위치에서
사용할 수 있습니다. `nyang-locale` 브라우저 쿠키에 선택을 1년간 저장하며 사용자 DB에는 저장하지 않습니다. SSR에서도 쿠키의 같은 값으로
렌더링합니다. URL과 로그인 상태를 바꾸지 않고 즉시 화면을 갱신합니다. 기본값은 한국어입니다.

## 관리 위치

- `app/locales/en.ts`: 영어 번역팩. 기존 한국어 UI 문장이 키이며 한국어는 원문을 사용합니다.
- `app/utils/locale.ts`: 순수 번역 및 동적 메시지 처리. Vue/브라우저 상태를 전역에 저장하지 않습니다.
- `app/composables/useLocale.ts`: 요청별 언어 상태, 쿠키 저장, 날짜 표시.
- `app/components/common/LanguageSwitcher.vue`: 테마 옆 언어 선택.

화면 문구는 `tr('한국어 원문')`으로 표시하고 영어 팩에도 같은 키를 등록합니다.
문구를 변경할 때 기존 키와 번역도 함께 수정합니다. 동적 안내는 `{0}`, `{1}`을 사용한
메시지 키로 번역하며, 번역의 치환 자리 수를 유지해야 합니다.

프로젝트명·일정 제목·설명·닉네임·사용자가 입력한 알림 메시지는 번역기에 넘기지 않습니다.
그 값이 번역 키와 같아도 사용자가 입력한 원문을 표시합니다. 에디터에서 새로 제안하는
기본 알림 메시지는 현재 언어로 생성하지만 이미 저장했거나 편집한 메시지는 바꾸지 않습니다.

날짜의 표시 문법, 달 이름과 요일을 바꾸되 모든 일정 시각 계산과 입력은 기존 KST 기준을
유지합니다. 문서 `lang`, 페이지 제목과 소셜 메타데이터도 선택 언어를 반영합니다.

현재 웹 UI를 지원하며 Slack 자체의 설치 승인 화면과 API 원문 응답 언어는 변경하지 않습니다.
언어별 URL이나 별도의 검색엔진용 다국어 페이지는 만들지 않았습니다.

확인: `node scripts/check-locales.mjs`. 브라우저에서 전환·재방문·모바일 레이아웃과
원문 보존을 추가 확인했습니다. 테스트 중 Slack 메시지나 실제 DB 쓰기는 실행하지 않습니다.

선택 메뉴의 `focusout.relatedTarget`이 null이면 즉시 닫지 않도록 보완했습니다. 바깥 pointerdown, 포커스가 실제 외부 요소로 이동한 경우, Escape로 닫습니다. `node scripts/check-appearance-focus.cjs`는 실행 중인 로컬 서버(기본 4320, `CHECK_BASE_URL`로 변경)에서 모션 감소 켬·끔, 의심 이벤트 주입, 쿠키·재방문·닫힘 동작을 모의 API로 검사합니다. 사용자는 수정 후 문제 PC에서도 실제 마우스 선택이 반영되는 것을 확인했습니다. 수정 전 이벤트 순서는 직접 기록하지 않았으므로 원인 추정과 해결 결과는 구분합니다.
