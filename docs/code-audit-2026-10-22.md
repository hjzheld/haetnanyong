## DB 성능 변경

`server/db/migrations/007-user-query-indexes.sql`에 tasks의 사용자/마감일,
events의 사용자/시간 시작 및 사용자/종일 시작 인덱스를 추가했습니다.
사용자 데이터 조회·캘린더·사용자 삭제의 전체 탐색 비용을 줄이는 용도입니다.
`schema.sql`에도 신규 DB용 정의를 반영했습니다.

**운영 DB에는 아직 적용하지 않았습니다.** 기존 DB에 schema.sql 전체를 실행하지 말고
007 마이그레이션만 별도 적용합니다. 큰 테이블은 인덱스 생성 중 쓰기 지연이 있을 수 있으므로
운영 환경의 마이그레이션 절차에 맞춰 적용합니다.

## 검증

- `npm run test:audit`: 잘못된 ID·날짜, 탈퇴 비밀번호/미확정 예약 보호, 캘린더 범위.
- `npm run test:reminders`: 예약 실패 분류, 대조, 소유권, 취소, OAuth/토큰 경로.
- `npm run test:workspace`: 캘린더 경계, 대시보드, 언어팩.
- `npm run test:performance`: 비동기 비밀번호, 세션 중복/경합, 계정, 날짜 직렬화, 표시 효과.
- `node scripts/check-workspace-ui.cjs`, `node scripts/check-plans-browser.cjs`,
  `node scripts/check-help-navigation.cjs`: 모의 API로 PC/태블릿/모바일, 입력·등록·재시도,
  드롭다운·모달 초점·삭제 오류 표시·뒤로가기·약관 UI 확인.
- `npm run lint`: 통과. `npm run build`: 통과. 초기 샌드박스의 상위 디렉터리
  readlink 제한으로 패키징이 실패했으나 권한 검토 후 동일 명령으로 완료했습니다.
- 빌드된 프로덕션 서버에서도 도움말·뒤로가기·약관 UI·모달 오류 표시 브라우저 검사를 통과했습니다.

브라우저 검사는 DB·Slack API를 모의 처리하며 실제 사용자에게 메시지를 보내지 않습니다.

## 검증 한계와 후속 작업

- 실제 Neon 마이그레이션, 실계정 탈퇴, Slack 발송/취소, Vercel 배포는 실행하지 않았습니다.
- Slack의 예약 성공 응답이나 ELAPSED는 수신자의 메시지 열람/푸시 수신 성공 증거가 아닙니다.
- 여러 요청 사이의 예약·이벤트 변경·연결 변경·탈퇴 경쟁을 완전히 직렬화하려면
  동일 DB 트랜잭션의 잠금과 경합 검증이 추가로 필요합니다. 이번 보호 검사를
  모든 동시 요청의 직렬화로 해석하면 안 됩니다.
- `/api/workspace`는 아직 전체 목록을 반환합니다. 대량 데이터에서는 페이지네이션과
  화면별 집계 조회로 옮길 필요가 있으며, 인덱스 추가만으로 응답 크기가 줄지는 않습니다.
