# 성능 점검 및 개선 기록

과거 성능 점검 기록입니다. 아래 측정값·검사 결과·파일 크기는 당시 실행 환경의 값이며 현재 운영 환경을 재측정한 결과가 아닙니다. 현재 기능 안내는 [프론트엔드 구조](frontend.md)를 참조합니다.

점검일: 2026-10-21. Nuxt/Vue 소스, API·인증·DB 접근, 화면 전환, 캘린더, 정적 파일 전달을 검토했습니다. 수치는 요청 수와 코드 경로 검증 및 로컬 비교 결과이며, 실제 사용자 전체의 페이지 속도 측정과는 구분합니다.

## 앞선 점검에서 반영한 내용

- 목록 API 네 개를 `/api/workspace`로 통합하고 인증을 요청 안에서만 공유.
- Slack 인증·연결 정보를 한 DB 쿼리로 조회.
- 캘린더와 목록이 같은 일정·태스크를 사용하도록 통일해 공유 캐시 충돌 제거.
- 로딩·오류·본문이 겹치지 않도록 표시 조건 수정.
- API `Server-Timing`에 서버·인증 DB 소요 시간 기록.

## 검증

- `npm run lint`: 타입 검사.
- `npm run test:performance`: 비동기 비밀번호와 기존 해시 호환, 요청별 인증 공유·사용자 분리, 세션 중복 제거, 계정·Slack 모의 검사, 날짜·월 경계, 캘린더 인덱스 동등성, reveal 검사.
- `npm run build`: 프로덕션 빌드.
- `node scripts/check-api-schema.mjs`: 실제 연결 DB의 SQL 55개 `EXPLAIN` 성공, 실패 0개. INSERT/UPDATE/DELETE는 실행하지 않음.
- `npm run test:performance:browser`: 모의 API를 사용하는 Playwright/Chrome 검사. 실제 계정 변경·Slack 전송 없이 로그인, 캘린더 필터, 로딩·본문 배타 표시, 상세 완료·삭제 흐름, 데스크톱·모바일 확인.
- `node scripts/check-frontend.mjs`: 공개 페이지 SSR·보안 헤더·이미지·API 인증 차단 확인.

브라우저 검사 실행:

```powershell
$env:NITRO_PORT = '4318'
node --env-file=.env .output/server/index.mjs
# 다른 터미널에서 실행. 기존 QA와 마찬가지로 Playwright와 Chrome이 필요합니다.
npm run test:performance:browser
$env:CHECK_BASE_URL = 'http://127.0.0.1:4318'
node scripts/check-frontend.mjs
```

캘린더 로컬 비교: 시간 일정 1,000개·날짜 31개에서 칸별 검색 **63.59ms**, 날짜별 인덱스 구성 **6.76ms**. 날짜별 결과 동등성을 확인했습니다. 캘린더 계산 부분의 비교이며 전체 사이트가 같은 비율로 빨라진다는 의미는 아닙니다.

## 남아 있는 비용과 운영 확인 사항

- 앞선 `SELECT 1` DB 왕복 측정은 664/606/201/202/202ms였습니다. 배포 서버·DB 리전과 유휴 후 지연은 운영 환경에서 확인해야 합니다. 이번에 리전·DB 운영 설정은 변경하지 않았습니다.
- 작업 화면은 전체 프로젝트·태스크·일정·리마인더를 받습니다. 데이터가 커지면 페이지별·월별 조회와 페이지네이션이 필요합니다. 이번에는 캘린더 표시와 수정 후 일관성을 유지하기 위해 응답 범위를 임의로 줄이지 않았습니다.
- PNG 원본은 약 0.55~0.80MB, favicon은 약 0.76MB입니다. 캐시·지연 로딩은 적용했으나 최초 전송량을 줄이려면 WebP/AVIF 파생본과 작은 favicon이 필요합니다. 원본 이미지는 변경하지 않았습니다.
- 미사용 컴포넌트·CSS 파일은 일부 있으나 로딩되지 않는 파일은 현재 번들 비용에 포함되지 않습니다. 기존 스타일 겹침은 외형 회귀 위험 때문에 일괄 삭제하지 않았습니다.
- 화면 전환용 세션 상태를 재사용하더라도 보호 API의 세션 만료·취소·소유권 검사와 요청 제한은 유지합니다.
- 실제 사용자 데이터로 전체 페이지 지연·LCP를 전후 비교하는 검증은 이번 모의 브라우저 검사와 구분해야 합니다.
