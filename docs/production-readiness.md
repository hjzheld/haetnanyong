# 운영 준비 체크리스트

## 이번에 적용된 항목

- 비로그인 사용자의 보호 페이지 접근 차단과 로그인 후 원래 주소 복귀
- 로그인 사용자의 로그인 페이지 재접근 차단
- 작업 중 세션 만료 시 현재 주소를 보존한 로그인 화면 이동
- 커스텀 404와 존재하지 않는 프로젝트 상세 404 처리
- 사용자용 오류 메시지 변환, 5xx 요청 추적 번호, 서버 오류 로그
- DB 기반 로그인·회원가입·Slack OAuth 시작·테스트 DM 요청 제한
- Origin/Sec-Fetch-Site 기반 교차 사이트 변경 요청 차단
- CSP, HSTS(운영), frame 차단, MIME 스니핑 차단, Referrer/Permissions 보안 헤더
- API 응답 `no-store`, 만료·폐기 세션 정리, 다른 기기 전체 로그아웃
- 표준 description, canonical, OG, Twitter Card, robots, sitemap, 보호 페이지 noindex
- 오프라인 안내, 삭제·연결 해제 확인 모달, 저장하지 않은 폼 이탈 경고

## 배포 전에 사용자가 설정할 항목

### 필수 환경변수

- `DATABASE_URL`: Neon PostgreSQL 연결 문자열
- `SESSION_SECRET`: 최소 32바이트 이상의 예측 불가능한 랜덤 문자열
- Slack OAuth 사용 시 `SLACK_CLIENT_ID`, `SLACK_CLIENT_SECRET`, `SLACK_REDIRECT_URI`, `SLACK_TOKEN_ENCRYPTION_KEY`(32자 이상)
- `CRON_SECRET`: 정기 취소·정리 작업 인증
- `SLACK_BOT_TOKEN`: 기존 수동 연결의 예약·취소 호환용. 새 OAuth 연결의 대체 설정이 아님

운영 환경에서는 HTTPS를 사용해야 하며, 프록시가 원래 Host와 Proto 헤더를 애플리케이션에 전달하는지 확인합니다.

### Slack

- Bot Token Scopes: `users:read`, `im:write`, `chat:write`
- 권한을 변경한 뒤 앱을 워크스페이스에 다시 설치
- 토큰 유출 시 즉시 폐기하고 재발급

### 브랜드 문구

프로젝트 전체 표기는 `했냐옹`으로 통일했습니다. OG에서도 같은 표기를 사용합니다. `했나옹`이 의도된 별도 표기라면 OG 문구만 다시 변경해야 합니다.

## 외부 서비스 또는 정책 결정이 필요한 항목

### 이메일 인증과 비밀번호 재설정

현재 메일 발송 제공자가 없어 구현하지 않았습니다. Resend, AWS SES, Postmark 등의 제공자와 발신 도메인을 정한 뒤 다음 데이터가 필요합니다.

- 일회용 검증 토큰의 해시
- 용도(이메일 인증/비밀번호 재설정)
- 만료 시각과 사용 완료 시각
- 발송 횟수 제한

토큰 원문은 DB에 저장하지 않고, 1회 사용 후 폐기해야 합니다.

### 회원 탈퇴

현재 비밀번호를 확인하고 예약 취소를 시도한 뒤 `delete_user_account` 함수로 계정과 서비스 데이터를 삭제합니다. 예약 ID가 없는 미확정 예약은 상태 확인을 먼저 하도록 409로 차단합니다. 취소 실패 또는 시간 예산으로 미처리한 예약의 채널·예약 ID는 취소 큐에 보관하며 정기 작업에서 재시도합니다. 필요한 설치 토큰과 DM 경로도 정리 조건 충족 전까지 유지합니다. 실제 운영 장애·동시 요청 검증은 남아 있습니다.

### 여러 서버로 확장할 때

요청 제한은 PostgreSQL `api_rate_limits`에 저장해 서버 인스턴스 간 공유합니다. 현재 같은 IP 기준 회원가입 1시간당 20회, 로그인 10분당 10회이며 고정 시간 구간을 사용합니다. 실패·차단 요청도 집계합니다. 프록시의 클라이언트 IP 전달 설정과 운영 DB 경합은 별도로 확인해야 합니다. 상세 기준과 해제 시각 표시는 [운영 안내](vercel-operations.md)를 참조합니다.

### 운영 관측과 복구

- Sentry 수집 코드가 있으며 DSN·소스맵 설정과 실제 수집 여부는 운영 환경에서 확인
- 요청 ID를 포함한 중앙 로그 보관
- Neon 백업·복구 정책과 복구 훈련
- 가동 상태 모니터링 및 알림
- 개인정보 처리방침, 이용약관, 문의 채널
- 일일 취소 크론이 오래된 예약을 최대 10건 재확인하는 코드가 있음. 시간 예산으로 처리가 줄 수 있으므로 실제 실행·지연 확인 필요

## 배포 후 확인

- 공유 디버거에서 OG 이미지와 문구 확인
- `/robots.txt`, `/sitemap.xml`의 도메인 확인
- 로그인 실패 제한과 정상 로그인 복구 확인
- 세션 만료 후 원래 페이지 복귀 확인
- 모바일·키보드 탐색·스크린리더 기본 점검
- Slack OAuth 승인, 테스트 DM, 예약, 취소를 실제 워크스페이스에서 각 1회 확인
