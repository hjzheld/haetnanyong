# Slack 알림 운영 및 복구

일정을 생성한 뒤 일정 상세 또는 프로젝트 일정의 Slack 알림 설정에서 별도로 예약합니다. 현재 알림은 `events` 기준이며 태스크 생성만으로 자동 알림을 보내지 않습니다.

새 예약 메시지의 `:paw_prints: 했냐옹` 머리말은 서버에서 고정해 붙입니다. 입력창에서는 본문만 수정하며, 고정 머리말을 포함한 전체 메시지는 최대 4,000자입니다. 기존 Slack 예약 메시지는 자동 변경하지 않습니다.

## 설정과 확인

- Slack App Home의 Home 탭을 구현하지 않아도 메시지를 예약할 수 있습니다. 메시지를 확인하려면 Slack 앱 설정의 App Home → Show Tabs → Messages Tab을 켭니다.
- 설치 권한은 `users:read`, `chat:write`, `im:write`입니다. 마이페이지의 연결 상태 확인은 현재 연결 토큰으로 `auth.test`, `users.info`, `chat.scheduledMessages.list`를 호출해 워크스페이스·사용자·예약 목록 접근을 검사합니다. 테스트 메시지는 보내지 않습니다. OAuth 설정은 [Slack 연결 안내](slack-oauth.md)를 참고합니다.
- 알림은 KST 입력을 명시적 UTC 오프셋으로 보내며, 현재부터 최소 1분 이후~120일 이내로 예약합니다. 테스트 시에는 직접 지정으로 5분 후를 권장합니다.
- 예약 성공은 Slack 예약 ID가 저장된 `SCHEDULED` 상태입니다. 기기 푸시 여부는 Slack의 알림 허용·방해 금지·앱 활성 상태 설정에도 영향을 받습니다.

## 실패와 재확인

| 상태                        | 동작                                                                       |
| --------------------------- | -------------------------------------------------------------------------- |
| FAILED                      | 명시적 예약 거부 또는 재확인 시 예약 없음. 원인을 해결한 뒤 다시 예약 가능 |
| UNKNOWN                     | 내부 오류·네트워크 지연 등으로 결과 불확실. 자동으로 중복 예약하지 않음    |
| SCHEDULING / CANCEL_PENDING | 진행 중 요청. 시작 후 2분 이내에는 재확인으로 덮어쓰지 않음                |
| SCHEDULED                   | Slack 예약 ID 확인. 실제 발송·수신 성공과는 별개                           |
| ELAPSED                     | 예약 시각이 지났고 Slack 예약 목록에 없음. 발송 성공으로 단정하지 않음     |
| CANCEL_FAILED               | 취소 재시도 가능                                                           |

`POST /api/reminders/{id}/reconcile`은 로그인 소유자를 확인하고 Slack 예약 목록의 모든 페이지를 대조합니다. 조회 실패나 불완전한 목록에서는 기존 상태를 보존합니다. 예약 ID를 잃은 새 요청은 채널·시각·메시지 해시를 대조합니다. 메시지 해시는 기존 `idempotency_key`에 저장하므로 추가 SQL 마이그레이션이 필요 없습니다. 기존 형식의 UNKNOWN에 동일 시각 예약 후보가 있으면 오인 취소를 막기 위해 미확정 상태를 유지합니다.

Slack 목록의 부재는 재확인 시점의 관측 결과이며 정확한 전달 증명이 아닙니다. 자동 재발송은 하지 않고 사용자가 새 시각으로 다시 예약합니다. 이미 지나간 시간의 메시지를 소급 발송하지 않습니다.

정상 발송된 메시지도 대기 예약 목록에서 사라지므로 현재 구현에서는 `ELAPSED`로 표시될 수 있습니다. 게시 여부의 자동 대조는 구현하지 않았습니다. DM 기록을 조회하는 `conversations.history`와 `im:history` 권한 등을 추가하면 게시 기록을 대조하는 방식으로 확장할 수 있지만, 메시지 읽음이나 기기 푸시 수신을 보장하는 검사는 아닙니다. [예약 목록 API](https://docs.slack.dev/reference/methods/chat.scheduledMessages.list), [메시지 기록 API](https://docs.slack.dev/reference/methods/conversations.history/)를 참고합니다.

목록과 일정 상세에서 상태 확인·다시 예약·취소를 제공합니다. 취소 시에도 미확정 예약을 먼저 확인하며, Slack이 `invalid_scheduled_message_id`를 반환하면 이미 제거된 예약으로 처리합니다. 상태 변경은 revision과 갱신 시각을 비교해 동시 요청이 최신 결과를 덮어쓰지 않게 합니다.

화면의 `상태 확인` 버튼은 결과가 불확실하거나 처리 중인 `UNKNOWN`, `SCHEDULING`, `CANCEL_PENDING`에만 표시합니다. `SCHEDULED`에는 표시하지 않습니다. 예약 시각이 지난 `SCHEDULED`와 `ELAPSED`는 `예약 시간 지남`으로 표시하고, 과거 예약을 취소하는 버튼과 발송 미확인 오류 문구 대신 Slack DM 확인 안내와 다시 예약 버튼을 제공합니다. 화면 표시는 서버 상태를 발송 성공으로 바꾸지 않습니다. 재예약 요청 시 서버가 과거 `SCHEDULED`의 Slack 대기 목록을 대조하며, 아직 대기 중이거나 조회가 실패하면 기존 예약을 덮어쓰지 않습니다. 재확인은 발송 증명 기능이 아닙니다.

## Vercel

일정 수정과 Slack 연결 변경·해제 요청도 활성 예약을 검사합니다. 지난 `SCHEDULED`만 있으면 정기 작업을 기다리지 않고 예약 목록과 대조한 뒤 DB 상태를 재검사합니다. 같은 DM 목록은 요청 안에서 재사용하며, 아직 대기 중·조회 실패·미확정 상태는 변경을 차단합니다. 외부 호출 예산은 15초이며 DB를 포함한 전체 응답 시간을 보장하지 않습니다.

예약 접수가 끝나면 Slack이 발송하므로 발송용 분 단위 크론이 필요하지 않습니다. 기존 `/api/internal/slack-cancellations` 일일 크론은 탈퇴 취소 작업과 함께 오래된 미확정·예약 상태를 최대 10건 재확인합니다. 실시간 상태 확인은 화면의 상태 확인 버튼으로 수행합니다. 크론에는 Vercel의 `CRON_SECRET` 환경변수가 필요합니다.

배포 후 기존 UNKNOWN 알림의 상태 확인을 누르고, 예약 시각 경과 또는 실패로 정리되면 새 미래 시각으로 다시 예약하세요. 로컬 코드 변경만으로 Vercel 배포본이나 기존 DB 상태가 즉시 바뀌지는 않습니다.
