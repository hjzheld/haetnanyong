# 전역 색상과 테마

`assets/css/variables.css`를 Nuxt 전역 CSS 목록 맨 앞에서 불러옵니다.
모든 CSS 파일의 고정 색상, 그라데이션 정지점, 반투명 색상, 그림자는 `:root`의
`--color-*` 변수로 관리합니다. 기본 밝은 테마와 코코아·로즈·세이지·미스트 블루 기반의
어두운 테마를 제공합니다.

## 테마 선택

767px 이하에서는 언어·테마 도구를 불투명한 배경의 하단 고정 바로 표시합니다. 바 높이와 안전 영역을 고려한 문서 하단 여백으로 개인정보처리방침·이용약관 링크까지 스크롤할 수 있습니다. 768px 이상에서는 기존 우측 하단 고정 배치를 유지합니다.

우측 하단 플로팅 버튼에서 밝게·어둡게·시스템 설정을 선택합니다. 기본은 시스템 설정이며
`nyang-theme` 쿠키에 선호도를 1년간 저장합니다. 시스템 설정에서는 기기 테마 변경도
즉시 반영합니다. 서버가 반환하는 head의 초기 스크립트가 스타일 로드 전에 테마를 적용하고,
Vue에서는 동일한 쿠키로 선택 상태를 복원합니다.

선택 UI는 `app/components/common/ThemeSwitcher.vue`, 상태는 `app/composables/useTheme.ts`,
배치는 `assets/css/theme.css`에 있습니다. 버튼 문구는 후속 다국어 작업을 위해 한 객체에
모았으며 현재는 `tr`을 통해 한국어·영어로 표시합니다. 브랜드와 사용자가 지정한 일정 색상은 테마 변경 시 유지합니다.

언어 메뉴와 함께 `focusout.relatedTarget`이 null일 때 즉시 닫지 않도록 보완했습니다. 모션 감소 켬·끔과 의심 이벤트를 넣은 로컬 Chrome 검사는 통과했고, 사용자가 문제 PC의 실제 마우스 선택도 정상 반영되는 것을 확인했습니다. 수정 전 이벤트 순서까지 확정한 결과는 아닙니다. 검사 명령과 범위는 [언어 선택 안내](localization.md)를 참조합니다.

## 이름과 역할

- `--color-background-page`, `--color-surface`: 페이지 및 기본 카드 배경
- `--color-text-primary`, `--color-text-muted`, `--color-text-on-accent`: 기본·보조·강조 배경 위 글자
- `--color-border`, `--color-border-*`: 경계선과 포커스 외곽선
- `--color-surface-*`, `--color-text-*`: 기존 화면에서 쓰던 배경·글자 변형 색상
- `--color-shadow-*`: 그림자 및 하이라이트, 알파 값 포함
- `--color-accent-*`: 지역 CSS 변수 등에서 사용하던 강조 색상
- `--color-brand-slack-*`: 브랜드 색상
- `--color-on-user-light`, `--color-on-user-dark`: 사용자 색상 위 대비 글자색

변형 변수의 색상 계열과 숫자는 기존 색을 식별하기 위한 이름입니다. 숫자는 HSL 밝기
0~1000이며, `a`는 불투명도 백분율입니다. 비슷하지만 서로 다른 기존 색은 임의로 합치지
않았습니다. 따라서 CSS 변수로 옮기는 과정에서 화면의 색이 변하지 않습니다.

## 테마를 추가할 때

`variables.css`의 기본 `:root` 아래에 있는 `:root[data-theme='dark']`를 참고해 선택자를 만들고,
배경·글자·경계선·그림자 변수를 역할별로 덮어씁니다. `color-scheme: dark`도 이 선택자에서
설정합니다. 테마 속성은 `document.documentElement`에 적용해야 전체 화면에 상속됩니다.
일부 핵심 변수만 바꾸면 변형 색상은 그대로 남으므로 각 그룹도 함께 정의해야 합니다.
브랜드 및 사용자 색상 위 대비 글자는 의도적으로 유지하는 것이 좋습니다.

기존 `--ink`, `--edge`, `--muted` 등의 지역 변수는 전역 색상 변수를 참조합니다.
테마는 이 지역 변수를 직접 덮어쓰기보다 해당 `--color-*` 변수를 덮어씁니다.

## 사용자 데이터는 테마와 분리

프로젝트·일정 색상은 사용자가 고르고 DB에 저장하는 데이터입니다. 색상 입력창과 API는
실제 HEX 값이 필요하므로 `var(...)` 문자열을 저장하면 안 됩니다. 새 항목의 기본값은
`app/utils/item-colors.ts`에서 관리하며 사용자가 저장한 값은 인라인 스타일로 유지합니다.
캘린더는 실제 색상의 밝기를 계산해 전역 대비 글자 변수를 선택합니다.

`transparent`, `currentColor`, `none`, 색상 선택기의 실제 값은 CSS 색상 토큰으로
기계적으로 치환하지 않습니다. 현재 Vue 파일에 별도의 `<style>` 블록은 없습니다.
`main.css`는 색상 참조를 정리했지만 기존처럼 전역 로드 목록에는 추가하지 않았습니다.
