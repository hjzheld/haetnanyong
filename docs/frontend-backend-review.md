# 프론트·백엔드 점검

## 변경 사항

- `v-reveal`: 소개 기능 카드, 프로젝트 카드, 홈 통계·정보 패널이 화면에 진입할 때 한 번 등장합니다. 브라우저 기본 IntersectionObserver/Web Animations API를 사용하며, 모션 줄이기 설정에서는 실행하지 않습니다. 언마운트 시 관찰과 실행 중 애니메이션을 정리합니다.
- Nuxt 4.5.2 / Vue Router 5.4.0으로 설치 의존성을 정렬했습니다. 기존 Nuxt가 Router 5용 타입 플러그인을 요청하면서 Router 4와 충돌하던 문제를 해소했습니다.
- 홈의 세션 복원을 라우트 미들웨어에서 실행하여 레이아웃이 로그인 상태를 결정하기 전에 세션이 준비되도록 했습니다.
- 비밀번호 변경 창은 `showModal()`과 `close()`로 엽니다. 처리 중 중복 요청과 닫기를 막고, 닫을 때 입력한 비밀번호를 지웁니다.
- 이메일 변경 시 현재 비밀번호를 확인하고 다른 세션을 해제합니다. 비밀번호 변경은 별도 API를 유지합니다.
- 계정 API 문서와 모의 계정 검사 스크립트를 분리된 비밀번호 API에 맞췄습니다.
- 비밀번호 입력의 서버 최대 길이를 200자로 제한했습니다.
- 소개 페이지에 중첩된 main 요소와 레이아웃의 중복 여백을 정리했습니다.

## 실행한 검사

- `npm run lint`: 타입 검사 통과. 기존 vue-router 타입 플러그인 오류 없음.
- `npm run build`: 클라이언트·SSR·Nitro 프로덕션 빌드 통과.
- `node scripts/check-account.mjs`: 프로필 입력, 이메일 재인증, 별도 비밀번호 변경, Slack 코드 인증·세션 귀속·재발송 간격·활성 알림 변경 제한 통과. DB와 Slack은 모의 구현입니다.
- `node scripts/check-calendar-dates.mjs`: DATE 직렬화와 한국 시간 월 경계 검사 통과.
- `node scripts/check-reveal.mjs`: 서버 렌더링 안전성, 화면 진입, 순차 지연, 관찰 해제, 애니메이션 정리, 모션 줄이기 통과.
- `node scripts/check-api-schema.mjs`: 실제 DB에서 SQL 46개의 EXPLAIN 성공. 쓰기 실행 없이 실행 계획만 확인했습니다.
- `node scripts/check-frontend.mjs`: 로컬 프로덕션 서버에서 소개·로그인 SSR, 가입 모드, 보조 링크 순서, 이미지 5개, 비로그인 페이지 이동, 보호 API 인증 차단, API 문서 확인 통과.

## 남은 범위와 제한

- npm audit에는 `braces`, `node-forge`의 취약점에서 파생된 high 경고 11개가 남습니다. 호환 범위 업데이트 후에도 남아 있는 하위 의존성 경고이며, 경고가 모두 해소된 상태는 아닙니다. Nuxt 자체에 직접 보고되던 경고들은 업데이트로 제거되었습니다.
- 실제 사용자 계정의 생성·수정·삭제와 실제 Slack 예약/발송은 실행하지 않았습니다. SQL 계획 검사와 모의 로직 검사가 실제 외부 서비스 전체 흐름의 성공을 보장하지는 않습니다.
- 브라우저 실제 화면의 시각적 검수와 동시 요청 부하 검사는 이번 자동 검사에 포함되지 않습니다.
- 로그인·가입 요청에는 서버 코드 기준 별도 시도 횟수 제한이 없습니다. 공개 운영 시 프록시나 공유 저장소 기반 제한이 필요합니다.
