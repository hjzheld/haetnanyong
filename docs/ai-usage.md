# AI 활용과 검증 과정

AI는 기획·구현·검사에 사용했습니다. 요구사항과 화면 방향, 우선순위는 제가 정하고 실제 사용 중 발견한 문제와 오류 응답을 바탕으로 수정 방향을 결정했습니다. 구현 코드뿐 아니라 자동 검사 코드에도 AI의 도움을 받았습니다.

## 역할과 책임

| 구분           | 수행한 내용                                                                                                      |
| -------------- | ---------------------------------------------------------------------------------------------------------------- |
| 직접 결정·진행 | 서비스 범위·디자인 방향·기능 우선순위, 외부 계정 생성·설정, 환경변수 입력, 배포, 실제 기기와 Slack에서 사용 확인 |
| AI의 지원      | 설계 대안과 코드 검토, 화면·API·SQL·검사 코드 작성, 오류 원인 분석, 이미지 제작, 문서 정리                       |
| 결과 확인      | 직접 사용한 결과·API 오류·AI 도구의 검사 결과를 비교하며 수정 요청. 모의 검사와 실제 서비스 확인을 구분          |

## 사례 1. 특정 PC에서 언어·테마 선택이 반영되지 않았던 문제

**발견과 비교:** 특정 PC에서 선택창은 열리지만 항목을 누르면 닫히기만 하고 설정이 바뀌지 않았습니다. 다른 기기에서는 정상이고 같은 PC에서도 자동 조작으로는 변경되었습니다. 발생 환경과 직접·자동 조작의 차이, 저장소 코드를 AI에 전달해 분석을 요청했습니다.

**근거와 조치:** 두 선택 컴포넌트가 `focusout`의 `relatedTarget`이 null인 경우까지 외부 이동으로 판단해 메뉴를 닫는 코드를 확인했습니다. 해당 환경의 모션 감소 설정에서는 닫힘 애니메이션도 없어 선택 처리 전에 메뉴가 사라질 가능성이 있다는 분석에 따라 null만으로 즉시 닫지 않도록 보완했습니다.

**검증과 판단:** 의심 이벤트를 주입한 모의 검사와 모션 감소 켬·끔의 로컬 Chrome 검사를 진행했습니다. 이후 사용자가 문제 PC에서도 실제 마우스 선택이 정상 반영되는 것을 확인했습니다. 수정 전 마우스 이벤트 순서는 직접 기록하지 않았으므로, 해결 결과와 원인 추정의 확실성은 구분했습니다.

## 사례 2. 구현 완료 후에도 Slack DM이 도착하지 않았던 문제

**발견:** AI의 도움으로 Slack 알림을 구현했지만 실제 Slack 계정에서 DM이 도착하지 않았습니다. 화면의 연결 표시만으로는 사용자가 알림을 받을 수 있는지 판단할 수 없었습니다.

**근거와 조치:** API 응답의 `messages_tab_disabled` 메시지를 근거로 Slack 공식 문서를 활용하여 앱의 Messages Tab 설정을 확인하고 직접 수정했습니다. 테스트 DM으로 즉시 발송 경로를 확인하고 실제 예약 메시지도 수신 확인했습니다.

**판단:** 연결 여부, 예약 접수, 실제 수신은 각각 확인해야 한다고 판단했습니다. `SCHEDULED`나 `ELAPSED` 상태만으로 수신 성공을 단정하지 않고 Slack에서 메시지가 도착했는지 확인했습니다.

이 사례의 실제 수신 확인은 해당 계정과 설정에서의 결과입니다. Slack 장애·권한 철회 등 다른 조건의 검증은 별도로 남아 있습니다.

## 사례 3. 보관 제안의 화면 조건을 서버에서도 확인하도록 보완

**요구사항:** 항목이 있는 프로젝트에서 모든 일정이 종료되고 할 일이 완료되면 보관 여부를 묻도록 요청했습니다. 미완료 프로젝트를 직접 보관하는 기능은 별도로 유지했습니다.

**발견과 수정:** AI 도구를 활용한 코드 점검에서 제안을 통한 보관 요청이 화면의 완료 판단에만 의존하는 부분을 확인했습니다. 서버에서 같은 조건을 검사하도록 보완했습니다. 화면을 확인한 뒤 항목 상태가 바뀌어 조건에 맞지 않으면 보관 요청을 거절하고 모달 안에 오류를 표시합니다.

**검증:** AI 도구의 모의 API 브라우저 검사로 실패 안내, 재시도 후 보관함 이동, 복원 직후 제안이 다시 뜨지 않는 동작을 확인했습니다. 이 결과를 실제 운영 DB에서 동시 요청까지 검증한 것으로 해석하지 않았습니다.

## 검증 결과를 해석한 기준

- 실제 사용에서 오류가 나타나면 API 응답과 재현 조건을 전달하고 수정 후 같은 흐름을 다시 확인했습니다.
- AI 도구가 작성·실행한 자동 검사는 그 조건에서의 결과로 기록했습니다. 실제 Slack 수신과 모의 발송 응답을 구분했습니다.
- 언어·테마 선택처럼 의심 이벤트를 넣은 검사가 통과해도 문제 PC에서 같은 원인이 발생했다고 확정하지 않았습니다.
- 대량 데이터·운영 DB 경합·외부 장애처럼 실행하지 않은 조건은 미확인 항목으로 남겼습니다.

확인한 결과와 남은 범위는 [검증 기록](validation.md), 기능 개요는 [README](../README.md)에 정리했습니다.
