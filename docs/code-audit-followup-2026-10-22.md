## 검증

- `npm run test:audit`: 완료/미완료·빈 프로젝트, 시간 및 KST 종일 종료 경계,
  조건부 보관의 409/404/성공, 수동 보관, 탈퇴의 남은 취소 작업 보존, 기존 입력/탈퇴/캘린더 회귀 검사 통과.
- `npm run test:workspace`, `npm run test:reminders`, `npm run test:performance`: 통과.
- `npm run lint`: 통과.
- `node scripts/check-plans-browser.cjs`: 기존 등록/재시도/모바일 검사와 함께
  새 프로젝트 상세 진입, 보관 오류의 모달 내 표시, 재시도→보관함 이동,
  복원 직후 제안 억제, 취소 유지, URL로 탭 변경, 캘린더→일정 플랜 이동 확인.
- `node scripts/check-workspace-ui.cjs`, `node scripts/check-help-navigation.cjs`: 통과.
- 빌드된 프로덕션 서버에서도 `check-plans-browser.cjs`의 등록·상세 진입·보관·복원·캘린더 이동 검사를 통과했습니다.
- `npm run build`: 통과. 처음에는 Windows 샌드박스의 상위 경로 readlink 제한으로
  Nitro 패키징이 중단됐고, 권한 검토 후 동일 명령으로 완료.

브라우저와 API 검사는 모의 데이터를 사용했습니다. 실제 DB 변경이나 Slack 발송·취소,
계정 탈퇴, Vercel 배포는 실행하지 않았습니다.

## 적용과 남은 범위

- 이번 변경에는 새 DB 마이그레이션이 없습니다. 기존 007 적용 여부는 별도로 확인해야 합니다.
- 탈퇴 큐는 기존 `delete_user_account` 함수와 정기 취소 작업을 사용합니다.
  20초는 Slack 취소 단계의 예산이며, DB·토큰 조회까지 포함한 전체 응답 시간 보장은 아닙니다.
- 조건부 보관은 UPDATE의 DB 스냅샷에서 조건을 확인합니다. 별도 동시 요청의
  할 일/일정 변경까지 완전히 직렬화하려면 생성·변경 경로에도 트랜잭션 잠금이 필요합니다.
- 전체 목록 API의 페이지네이션과 실제 운영 데이터 규모에서의 지연 측정은 후속 범위입니다.
- 배포 후 완료 프로젝트의 보관/복원, 취소 후 재팝업 여부, 진행 중/보관함 이동을 직접 확인합니다.
